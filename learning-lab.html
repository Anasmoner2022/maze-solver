The mental model
A call is a bookmark


Imagine each call holding a bookmark at line 40: “I am at this cell, and I am waiting for this neighbor.” Calling solve(next) adds a bookmark above it. Returning removes the top bookmark and delivers a value to the one underneath.


Going deeper: only the newest frame runs. A parent does not keep looping in the background. It remembers its direction and waits for its child to finish.


Backtracking: the child returns null. Its parent resumes and tries another direction. The code does not literally move a player backward and does not set visited cells back to false.


Success unwinding: E returns [E]. Its parent returns [parent, E]. The next parent prepends itself again. The final array is ordered from S to E. Once success is found, remaining directions are skipped.


Three different things: the stack is unfinished calls; visited is a lasting record of explored cells; the returned array is the successful route. A rejected call can be on the stack without its cell being visited.




Understand the whole project
From text to answer
    

  • node index.js maze.txt passes the file path through process.argv[2]. Missing arguments print usage and exit.
    • 

  • loadMaze() reads text, removes empty lines, trims trailing whitespace, splits each row into characters, and locates S and E. It rejects empty, ragged, invalid-character, missing-endpoint, and duplicate-endpoint inputs.
    • 

  • index.js creates a same-shaped grid of false values, then calls solve(grid, visited, start, end).
    • 

  • A returned array is painted as * on a copy of the grid, preserving S and E. A null result prints “No path exists.”
    • 

  • One project quirk: both maze.js and solver.js contain demonstration code outside their functions. Importing them also runs that code, so the command prints extra demo output before the actual answer. The lab models the requested solve call only.

Predict, then reveal
Check your understanding


Why does a wall still create a stack frame?
The recursive call is made before its checks run. The new frame checks bounds, then the wall, and returns null. The caller does not pre-filter neighbors.


Why is E still false in visited?
The end guard at line 30 returns at line 31, before the visited assignment at line 35. Reaching E succeeds without marking it visited.


What if you remove the visited check?
Adjacent open cells can keep calling each other. For example A calls B, then B calls A again. The call stack can grow until the runtime reports a stack overflow.


Does null mean “this cell is a wall”?
No. It can mean out of bounds, a wall, already visited, or all four directions failed. Only null from the root means the entire search failed to find E.


Does this find the shortest route?
No. Depth-first search returns the first successful route under Up, Down, Left, Right order. Breadth-first search would find a shortest route in this unweighted maze.


Are the returned arrays the same object?
No. [current, ...result] allocates a new array and copies the child's elements after current. The coordinate objects inside are reused; the arrays themselves are new.


How much work and memory does this need?
Let V be the number of cells, and L the successful path length. Search visits each reachable non-end open cell at most once and tries up to four neighbors: O(V) search work. This implementation also copies arrays of length 1 through L while unwinding, adding O(L²) copying time. The visited grid and recursion depth use O(V) space. Copied arrays may coexist during unwinding, so this return-building strategy can also use O(L²) live array-element storage. Very deep mazes can overflow the JavaScript call stack.
